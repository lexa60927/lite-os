# lite-os
легкая операционная ситсема

## LiteCraft — 3D-воксельная игра (браузер)

Песочница в духе Minecraft: бесконечный процедурный мир, копка и установка блоков,
деревья, руды, пещеры, вода, факелы, цикл дня и ночи, сохранение мира в браузере.
Всё на Three.js, без единого внешнего ассета — текстуры, звуки и музыка генерируются кодом.
С 0.3.0: настоящие тени от солнца, вода с отражением мира и лёгким покачиванием, еда,
кремень с яблоками, компас и часы, лимит кадров и дальность прорисовки до 64 чанков.

### ⚠️ Мир пустой / чанки невидимые — читать ПЕРВЫМ

Единственный известный способ получить «генерация идёт, а чанков нет» —
**отравленный одно-слотовый кэш `World.getChunk`** и **частичный чанок в кэше**.
Эти три места (`getChunk`-кэш, `World.ensureChunk`, `streamPlan`/`dirtyMesh`)
трогать нельзя без новых замеров; проверка — `npm run test:stream`, она падает
ровно на этих сценариях.

Симптом: `чанков: 351 (мешей 88, в очереди 0)` — данные есть, геометрии нет,
очередь пуста, стриминг считает, что всё готово.
Воспроизведение: `node dev/render-view.mjs --seed 123451101 --cx 5 --cz -1` и
`dev/test-stream.mjs`; история — коммиты «getChunk врал про уже сгенерированный
чанк» и «падающий чанк больше не может остаться невидимой дырой навсегда».
Что проверять по порядку: (1) кэшируется ли `null` в `getChunk`; (2) кладётся ли
чанк в `chunks` до `terrain.generate`; (3) не выбрасывает ли `neighborsReady`
чанки из очереди без возврата; (4) не проглочено ли исключение — счётчики
 видны в F3 (`сбой: ген N, меш M`) и в тосте.

### Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # прод-сборка в dist/
npm test           # смоук-тест всей игры в Node (физика, добыча, крафт, мобы, сохранение, UI)
npm run test:shaders  # GLSL-парсер: все uniforms объявлены, синтаксис в порядке
npm run test:api      # все this.<модуль>.<метод>() из main.js реально существуют
npm run test:villages # деревни: плотность, планировка, детерминизм на границах чанков
npm run bench:mesh    # профиль стриминга: мс на генерацию и меширование чанка
npm run test:calm     # численная проверка «спокойных» тайлов (шум на 1px = рябь)
npm run test:uv       # ориентация и посадка текстур: атлас ↔ UV ↔ грани (ловит «вверх ногами»)
npm run test:stream   # политика стриминга: бюджет не должен морить очередь (ловит «пустые чанки»)
npm run test:net      # сеть: протокол, интерполяция, кадры WebSocket, живое реле, игра целиком
npm run test:render   # рендер без браузера: инварианты GLSL, математика теней, куб-проба, настройки, новые предметы
npm run net           # своё реле для мультиплеера: ws://0.0.0.0:8790/<комната>, зависимостей нет
npm run render:tiles  # лист тайлов атласа в PNG, чтобы смотреть текстуры глазами
npm run render     # PNG-превью мира без браузера (софтверный растеризатор по тем же мешам)
```

Собственная версия игры лежит в [`docs/`](docs/) — это `dist/`, зафиксированный в
репозитории, чтобы в игру можно было играть по ссылке (GitHub Pages) или просто
скинуть папку на любой статический хост: пути в сборке относительные
(`base: './'`), поэтому подпуть вида `/lite-os/docs/` работает. Обновлять после
изменений в коде:

```bash
npm ci && npm run build && rm -rf docs && cp -r dist docs && touch docs/.nojekyll
```

Двойным кликом `index.html` из распаковки не откроется: браузер не грузит ES-модули
по `file://`, нужен сервер (`python3 -m http.server` в каталоге с игрой).


### Производительность (замерено `npm run bench:mesh`, 121 чанк, seed 42)

* **меширование: 5.86 → 4.59 мс/чанк** (−22 %), а мусор на чанк при мешировании — 75 КБ вместо ~1.1 МБ (замер `process.memoryUsage().heapUsed` на 121 чанке). Два приёма: мемо-маска
  непрозрачности в `QuadBuffer`-проходах (шесть проб на клетку и 16 угловых на
  квад стали одной загрузкой из `Uint8Array`) и **пул буферов** вместо
  `new QuadBuffer(4096)` + `new QuadBuffer(1024)` на каждый чанк — раньше это
  было ~1.1 МБ обнулённых массивов на чанк, то есть ~0.5 ГБ мусора на стартовый
  радиус 10 и постоянные паузы сборщика мусора;
* **водяной буфер заводится только если вода в чанке есть** (у 8 чанков из 10
  её нет) и отдаётся в пул;
* геометрия в GPU уходит **ровно полезным размером** (`QuadBuffer.take()`
  режет по числу квадов), а `ChunkView.applyMesh` переиспользует буферы только
  при совпадении типа массива — `set()` из `Uint32` в `Uint16` молча обрезал бы
  индексы, и грань просто перестала бы рисоваться;
* **настройка «Разрешение рендера»** (0.5–1): framebuffer = `min(devicePixelRatio, 2)
  × масштаб`; 0.65 на встроенном GPU снимает почти половину закрашиваемых
  пикселей, а на пиксель-арте с `Nearest` это почти незаметно;
* **«Слабое железо»** в настройках — пресет одной кнопкой: 65 % рендера, без AO,
  облака 30 %, мобы 8. `renderDistance` пресет не меняет: 10+ чанков должны
  работать, а не подрезаться;
* генерация чанка — 4.6–5.4 мс, меширование — 4.6 мс: при бюджете 6 мс/кадр это
  ~1 чанк на кадр, поэтому при ходьбе мир достраивается кольцом с упреждением, а
  при старте радиуса включает режим всплеска (см. «Генерация — как в Minecraft»).

* **лимит кадров** — настройка «Лимит кадров, FPS», по умолчанию 120, от 20 до 240 и
  «без лимита». Кадры не копятся в очереди, а просто не рисуются: `frame()` выходит до
  физики, а она считает мир фиксированным шагом 1/60 и догоняет сама. Поэтому на 20 к/с
  игрок идёт ровно так же, как на 240 — это единственное, что ломает такие лимиты при
  наивной реализации. Запас в 1.2 мс снимает джиттер вертикалки: без него лимит 60 на
  60-Гц мониторе резал бы каждый второй кадр. Замерено в смоук-тесте (24 кадра по 16.7 мс:
  без лимита 23 подшага мира, с 20 к/с — 21);
* **дальность прорисовки 2…64 чанка** (`setRenderDistance`). Бюджет потоковой генерации
  растёт вместе с радиусом — на дальней дистанции это 6 мс/кадр вместо 3, иначе мир
  «догоняет» игрока вечностью, — а уборка дальних чанков (`cullFarChunks`) включается
  только когда чанков действительно много; на радиусе 10 она не нужна и не работает;
* **карта теней не перерисовывается каждый кадр**: `renderer.shadowMap.autoUpdate = false`
  и `needsUpdate` по смене блока, в котором стоит игрок, либо раз в 6 кадров — сама камера
  теней всё равно следует за игроком, просто шагом не дёргает картинку.

Отменённая проба (записана в `mesher.js` комментарием): пропуск «глухих» клеток
по нижней границе воздуха в колонке. Число квадов не изменилось, а время выросло
на 0.5 мс/чанк — проверка `ly < start[c]` дороже, чем шесть обращений к маске.

### Режимы мира

Режим выбирается на главном экране, рядом с сидом, и записывается в сохранение
мира — у каждого мира он свой.

| Режим | Что даёт |
| --- | --- |
| Выживание (по умолчанию) | всё добывается руками и расходуется, работает урон, полёта нет |
| Творчество | полёт, палитра всех блоков и предметов, стек не тратится, урон не страшен |

Переключить режим на ходу можно кнопкой в инвентаре или галкой в настройках;
переключение в выживание сразу гасит полёт, чтобы игрок не повис в воздухе.

Урон от падения: 4 первых блока свободные, дальше по полсердца за блок. Падение
с дерева (10 блоков) — 1.5 сердца, с холма (20) — 4 сердца, с горы (40) — 9;
смертельно примерно с 44 блоков. Раньше был 1 HP за блок — смерть уже с 24, что на нашем
на нашем рельефе это означало «упал и сразу подох» с любого обрыва.

### Выживание, крафт и мобы

Новый мир стартует в **выживании**: блоки добываются и тратятся, инструменты нужно
крафтить. Творческий режим включается галкой в настройках (блоки не тратятся, урон
не страшен, хотбар заполняется палитрой).

* **Инвентарь** — 9 слотов хотбара + 27 в рюкзаке, стак 64. Клик по клетке берёт стек,
  клик по другой кладёт/меняет. `Q` — выбросить.
* **Добыча** — из камня летит булыжник, из травы — земля, из листвы — саженцы.
  Скорость зависит от инструмента: `кирка` для камня/стекла, `топор` для дерева,
  `лопата` для земли/песка/дёрна; неподходящим инструментом блок копается втрое медленнее.
* **Инструменты и оружие** — 17 предметов (дерево, камень, железо, алмаз × кирка,
  топор, лопата, меч, плюс ножницы): скорость 2.4 / 3.6 / 5.6 / 8.2, урон 2 / 3 / 5 / 7.
  Ножницы (4.2 по дёрну, растениям и шерсти) срезают траву и цветы, не превращая их в палки.
* **31 рецепт** — доски, палки, верстак, факелы, булыжник, стекло, кирпич, все инструменты,
  а с 0.3.0 ещё замшелый булыжник (булыжник + саженец), лёд (4 снега, у верстака), фонарь
  (стекло + кремень + уголь, даёт 2 штуки), кремень из гравия, хлеб (3 пшеницы, у верстака),
  компас (4 железа + изумруд) и часы (4 золота + редстоун) — последние три тоже у верстака.
  Простые собираются в инвентаре, всё с камнем и металлом — только рядом с верстаком (в 4 блоках).
* **Еда** — яблоко (+2 сердца) и хлеб (+4). ПКМ, держа их в руке: съедается один предмет,
  дальше пауза 0.9 с, иначе стек ушёл бы за одно нажатие. В творчестве еда не нужна и
  не работает, на полном здоровье — тоже, про это пишет подсказка.
* **Бонусные дропы** — гравий в 16 % случаев вместо земли даёт кремень, листва в 14 % —
  яблоко. Шанс считается из координат (`bonusDropOf`), а не из `Math.random()`: сосед по сети
  получит ровно тот же предмет, что и вы, потому что мир у всех детерминирован.
* **Мобы** — свинья, корова, овца (мирные, день), сумеречник и пещерник (агрессивные
  ночью и в темноте; сумеречник горит на солнце). У мобов своя воксельная геометрия,
  та же физика AABB-коллизий, они пасутся, убегают от удара, падают и тонут.
  С них падает мясо, кожа, шерсть, уголь, светокамень. Число мобов вокруг — в настройках
  (0 = выключить).

### Растения

Травинки, папоротники, цветы, пшеница и саженцы рисуются крестовиной высотой
`plantH` из `BLOCKS` (0.42–0.72 блока), а не на весь блок, и растут куртинами:
плотность модулируется шумом по сетке 2×2 (`hash2(x >> 2, z >> 2)`), поэтому на
лугу чередуются заросли и вытоптанные пятна. Раньше в саванне травинка была на
30% клеток и стояла в полный блок — вместо луга получалось поле зелёных
штырьков, что и выглядело как «сломанные текстуры».

### Мир

Десять биомов (равнины, лес, тайга, саванна, пустыня, снега, болото, горы, пляж, океан),
горные хребты, пещеры с озёрами, руды по глубине, снежные вершины. Трава и листва
окрашиваются оттенком биома через вершинный атрибут `tint`, поэтому один и тот же
тайл на лугу, в лесу и в саванне выглядит по-разному. Дальность прорисовки — до 16 чанков
(~256 блоков): туман начинается на 55% дистанции и полностью закрывает только край
прокрутки, так что мир не обрывается в пустоту. Чанки генерируются по запросу для любого
сид-координате — проверено тестом на ±5100 блоков.

### Деревни

Регион 96×96 блоков с ~28% вероятностью становится деревней, если биом подходящий
(равнины, лесостепь-саванна, пустыня, тайга, снега), рельеф плоский (перепад ≤ 6) и
суше уровня моря. Планировка — сетка 3×3 клетки 32 блока: улицы между клетками,
в центре площадь с колодцем и четырьмя фонарями, по углам дома, на сторонах света —
огороды и дворы. Строит генератор из чанковых координат, как деревья: любой чанк
восстанавливается независимо, и на стыках дома не разъезжаются (это отдельная проверка
в `npm run test:villages` — застройка сравнивается при двух порядках генерации).

* **Дом**: стены из досок (в пустыне — песчаник, в тайге и снегах — булыжник), углы и
  притолока из брёвен, окна из стекла, дверь на стороне площади, пол, перекрытие,
  крыша с парапетом и коньком, труба, светокамень-фонарь на коньке у высоких домов.
* **Огород**: грядки (`farmland`) через ряд с пшеницей, пруд, стог сена, изгородь из брёвен.
* **Житель** (`mobs.js`): появляется только в деревне, мирный, несёт изумруд.
  Агрессивные мобы в деревне не спавнятся — площадь освещена и безопасна.
* Новые блоки: **грядка**, **пшеница**, **стог сена**, **изумруд** (id 59–62; `BLOCKS`
  индексируется по id, поэтому новые записи — только в конце массива, за инструментами).

Вход в деревню игра отмечает подсказкой, в отладочной панели (F3) видно `деревня`,
а заодно стоимость стриминга в мс на кадр — по ней удобно проверять, что мир больше не
дёргается.


### Шейдеры (Настройки → «Шейдеры»)

Четыре уровня, одна программа — уровень это всего лишь униформа `uQuality` (плюс
`uShadow` и `uRefl`), поэтому переключение мгновенное и без перестройки чанков:

| Уровень | Что включено |
| --- | --- |
| **Выкл** | ровно та картинка, что была раньше: альбедо × свет от лица чанка. Формулы совпадают бит-в-бит — это честный режим сравнения и спасение на самом слабом железе |
| **Мягкие** | нормали из производных экрана (`dFdx/dFdy`), солнечный коэффициент по грани, ACES-тонмаппинг, дымка по высоте, блик и френель на воде |
| **Красивые** | то же + rim-подсветка от неба, перенасыщение цветов, виньетка на HUD, тени от солнца — «пост-обработка» без постпрохода |
| **Ультра** | то же + свои ветки в небе (физика цвета, закат, звёзды) и в воде (куб-проба отражений), финальный грейд-проход, мягче тени. Нужна приличная видеокарта; без неё всё это молча выключается, и картинка остаётся |

`src/render/voxelMaterial.js` — весь GLSL; `sky.js` каждый кадр отдаёт материалу
направление солнца (`uSunDirW`) и время (`uTime`). Ночью солнце не уходит под
отрицательную высоту специально: иначе нижние грани освещались бы сильнее верхних.
Проверяется `npm run test:shaders` (парсер GLSL + сверка всех `uniforms` с
объявлениями в коде) — в Node шейдер не исполняется, так что глазами это видно
только в браузере.

### Тени и вода (0.3.0)

Солнце — настоящий `DirectionalLight` с ортографической картой теней 2048², которая ходит
за игроком. Зона 128 блоков (тени «рядом») или 192 («широко») — это 12.8…16 блоков на
пиксель теневой карты; камера привязывается к сетке этого пикселя (`_texel`), иначе тени
кишечили бы на каждом шаге. `bias -0.0006` и `normalBias 0.14` — компромисс: меньше
начинает мерцать на длинных гранях, больше — тень отрывается от блока. Листва, трава и
факелы отбрасывают «дырявую» тень, а не прямоугольник: для прохода глубины висит
`MeshDepthMaterial` с тем же атласом и `alphaTest 0.5`.

Ночью теней нет вовсе (`sunShadow.update()` возвращает false), днём их сила равна
`0.92 × clamp(день × 1.5 − 0.05)`, на закате мягче. Выключенные тени буквально возвращают
прежнюю картинку: `USE_SHADOWMAP` существует только при включённом `renderer.shadowMap`,
поэтому шейдер собирается в ровно тот же код, что был до этой функции.

Вода в «ультре» берёт отражение из куб-пробы (`waterProbe.js`): `CubeCamera` снимает мир с
граней 128³ с позиции камеры, раз в 12 кадров, меши воды на время съёмки скрыты, а сама
съёмка идёт **после** основного кадра — иначе каждая проба гоняла бы проход карт теней
заново. Поверх пробы — отражение неба и фильтр Френеля (`pow(1 - dot(V, n), 4.2)`, сверху
ограничен 0.58, чтобы озеро не становилось зеркалом), блик по половинному вектору и волна
амплитудой 0.022 блока. «Небольшое покачивание» — из требования: с амплитудой 0.055 вода
выглядела штормом.

Свечения (bloom) здесь нет намеренно. Первая версия «ультры» стояла на
`UnrealBloomPass`, и с ним солнце превращалось в молочно-белое пятно, а яркость неба
уползала за 1.0: постпроход усиливает всё, что ярче порога, а ярче порога у нас оказалось
всё небо. Вместо него `postfx.js` делает только грейд — ACES, дымку, виньетку и подводный
цвет, — солнце и луна зажаты в 0..1, а HDR-буфер заменён на `UnsignedByte` с MSAA 4×
(иначе на части драйверов получаем 8-битную картинку с полосами).

`npm run test:render` проверяет это без браузера: GLSL (тени подключены в обеих стадиях,
никакого `colorspace_fragment`, амплитуда воды ≤ 0.03), математику `SunShadow` (пиксельный
шаг, радиус, «ночью теней нет»), флаги мешей, деградацию пробы без GL и то, что настройки
доходят до униформ.

Вода на «ультре» (0.4.1) почти прозрачная всмешку: смотришь вниз — видно грунт и
песок у берега, смотришь вдоль — зеркало. Отражение неба считается аналитически
(градиент + узкий диск солнца и широкий ореол), куб-проба мира подмешивается только
вниз по лучу отражения — вверху она размывала небо в мутное пятно. Никакого bloom:
блик — это законное отражение солнца на волне, а не раздувание яркости кадра.
Покачивание осталось маленьким (2–4 см), иначе вода «кипит».

### Креатив и палитра всех блоков

Режим включается чекбоксом «Творчество: блоки не тратятся, урон не страшен» в настройках или кнопкой **Творчество: вкл**
прямо в инвентаре (`E`) — режим сохраняется между запусками и влияет на хотбар,
трату стеков и подсказку при спавне.

В креативе палитра показывает **все 72 блока и предмета** (всё, что имеет
текстуру; `render:'none'`-заглушки не показывает), но не списком по id, а
категориями — Стройка / Природа / Руды и свет / Растения и ферма / Инструменты /
Предметы — со строкой поиска по русскому названию или ключу (`кирка`, `wool`,
`lantern`). Клик по клетке кладёт блок в выбранный слот хотбара, числа не тратятся.

Линейка сердец в творчестве прячется: урона там нет, а пустая полоска только
намекает, что что-то сломалось. Возвращается при переключении на выживание.

### Сетевая игра (мультиплеер)

Кнопка **«Сетевая игра»** — в настройках, **«Сеть»** — в главном меню (можно зайти в комнату ещё без мира: игра сама подготовит его из поля сида). Мир по сети не
передаётся: он детерминирован из сида, поэтому по проводам летают только сид
один раз, правки блоков и поза игрока 12 раз в секунду (получатель интерполирует,
молчавшего 15 с выбрасывает). Протокол — JSON-сообщения `hello`/`seed`/`p`/`e`/`c`/`bye`
в `src/game/net.js`, вся входящая валидация (координаты, id блока, длина имени,
размер пакета) — там же, потому что один кривой пакет от чужого клиента не должен
ронять меширование чанка.

Два способа играть:

1. **Через реле.** Кто-то один запускает `npm run net` (зависимостей нет: node http
   + own WebSocket-фрейминг), остальные вводят адрес вида `ws://192.168.0.5:8790` и
   имя комнаты. Реле — тупой широковещатель: правил игры не знает, переносить его
   на VPS можно как есть. Комната = путь URL, до 16 игроков, лишний отклоняется.
2. **Вдвоём без сервера (WebRTC).** Хост жмёт «Создать код приглашения», отправляет
   строку второму игроку (мессенджер, почта — что угодно), тот вставляет её и
   нажимает «Вставить и ответить», возвращает полученный код. Это ручной
   сигнальный обмен: сервер нужен только чтобы познакомиться, дальше трафик
   идёт напрямую. В одной сети работает всегда, через NAT — как повезёт без STUN.

Гость при входе перенимает сид хоста и пересобирает свой мир (`start()`), поэтому
дальше у обоих одна и та же генерация, а расходятся только правки — они применяются
через обычный `world.setBlock(..., record=true)`, то есть попадают и в сохранение,
и в меш, и соседу обратно. Свою добычу/установку игра рассылает одна точка —
`netBroadcast()`, эха нет. Остальные игроки видны в мире как аватары с табличкой
имени (`src/render/avatars.js`), ночью они темнеют вместе с миром. Чат — в панели
сети, сообщения прилетают тостом.

`npm run test:net` проверяет всё это по-настоящему: кодек и валидацию, лимит
частоты пакетов, интерполяцию, отбраковку мусора, разбор WebSocket-кадров
(включая замаскированные и обрывок на границе пакета), живое реле на реальном
порту — и наконец целую `Game` в комнате с другим игроком: чужая правка должна
изменить блоки в моём мире, а моя — долететь до соседа.

### Свои моды и шейдеры (0.4.0, в игре выключено с 0.4.3)

> **С 0.4.3 загрузка своих модов в игре выключена**: `mods/*.js` не подхватываются,
> секции «Моды» в настройках нет, сохранённые в браузере моды не читаются. Причина:
> GLSL мода вставляется в ОДИН общий воксельный материал, и одна несобранная на
> чьём-то драйвере программа убирает с экрана весь мир — небо, облака, рука и рамка
> цели при этом остаются, потому что живут на своих материалах. Сам механизм цел:
> `src/game/mods.js`, справочник и `npm run test:mods` работают, возвращается всё
> это одной строкой `MODS_IN_GAME = true` в `src/main.js`.
>
> Вдобавок игра больше не может остаться с пустым экраном: если GPU не собрал
> материал мира, она спускается на лёгкий материал (свет и дымка есть, теней и
> отражений нет), а если и он не соберётся — на базовый `MeshBasicMaterial`.
> Ступень и текст ошибки драйвера видны в F3; `npm run diag` и `npm run diag:sweep`
> прогоняют те же проверки дома, без браузера.

Игру можно расширять, не трогая её исходники: свои блоки, предметы, рецепты, мобы,
руда в рельефе и свой GLSL. Мод — это один объект-описание; справочник по всем полям
в [`mods/README.md`](mods/README.md), три готовых примера лежат рядом с ним.

Два способа доставить мод:

* **файл в `mods/`** — сборка подхватывает каталог сама (`import.meta.glob`), зато
  доступны функции: свой `paint` для тайла, `shader.frag` как функция;
* **текст в Настройки → «Моды»** — работает и на собранной версии с GitHub Pages,
  где никакого сборщика нет; мода хранится в `localStorage` этого браузера.

Что гарантирует игра:

* **без модов ничего не меняется**. Ни числа тайлов в атласе, ни строка шейдера:
  `buildVoxelShaders({})` обязана равняться исходному `VOXEL_FRAG` — за этим следит
  `npm run test:mods` (11 блоков проверок, 100+ утверждений);
* **битый мод не роняет игру**. Мод проверяется целиком и применяется атомарно; если
  что-то не так — в панели висит причина («блок a_b ссылается на тайл «net», которого
  нет»), остальные моды применяются как ни в чём не бывало;
* **свой шейдер — это вставка в наши четыре якоря** (`vert`, `frag`, `fragFinal`,
  `post`), а не отдельная программа: three не пересобирает программу на каждое
  движение, и все шейдер-уровни (включая «выкл») остаются в силе. Код проходит
  валидатор до вставки: без `main`, без препроцессора, без записи в `gl_FragColor`,
  только те униформы, которые мы обещаем. Иначе это чёрный экран, а не ошибка в консоли;
* **ручки модов живые**: `shader.uniforms` превращаются в слайдеры 0…1 в той же
  панели, `game.mods.setUniform('uAmount', .9)` — из консоли;
* **своя руда детерминирована** (хеш от координат и сида, никаких `Math.random`),
  поэтому соседи по сети видят те же жилы, а `test:world` по-прежнему считает
  генерацию неизменной: без модов `world.modPass` не выставлен вовсе;
* **примеры выключены по умолчанию** (`enabledByDefault: false`) — сама папка `mods/`
  картинку не меняет, только галка в настройках.

Одно ограничение честное и неустранимое: id блока — это байт в чанке, а атлас
строится один раз. Поэтому мод, который *добавляет* блоки или тайлы, применяется
перезагрузкой (F5), и набор включённых модов с блоками лучше держать стабильным:
выключишь один — id последующих сдвинутся, и старые блоки покажутся чужими. Правки
мира с id, которых нет в текущем наборе блоков, игра выбрасывает при загрузке —
чанк от выключенного мода останется видимым, а не пустым.

### Что внутри

```
src/engine/    шум, блоки, генератор мира (биомы, пещеры, руды, деревья), мешинг чанков
src/render/    атлас пиксельных текстур, материал чанков (шейдеры четырёх уровней), тени солнца,
               куб-проба отражений, финальный грейд, небо, частицы, руки,
               аватары сетевых игроков
src/game/      игрок и физика, рейкаст по вокселям, инвентарь, крафт, мобы, WebAudio-синтез, сохранения,
               сетевой протокол и транспорты (реле/WebRTC)
src/ui/        HUD, инвентарь, меню, настройки, тач-управление
dev/           тесты и отладочные скрипты (смоук-тест гоняет игру на заглушках DOM)
```

Текстуры — атлас 512×512 (16×16 ячеек по 32 px, тайл 16 px + 8 px дублированной
кромки). Маппинг: `NearestFilter` вблизи, `LinearMipmapLinear` + анизотропия до 8 вдали —
иначе наискось уходящая в гориз поверхность рябила сеткой. Степень двойки выбрана не
случайно: с ней mipmap легален в любом WebGL-контексте.

Растения (крестовины) — без `fullBright`: свет берут общий с рельефом, иначе в
полдень луг светится кислотно-жёлтым на фоне затенённой земли. Силуэт
папоротника расширяется книзу (кверху — читается как перевёрнутый), высота
квада 0.38–0.62 из `plantH`, а `alphaTest` у твёрдого материала 0.15, не 0.4:
на дальних mipmap-уровнях 16-пиксельный тайл усредняется до α 0.2–0.4, и с
порогом 0.4 трава пропадала за полем зрения.

Ориентация тайла закреплена тестом `npm run test:uv`, потому что «текстуры вверх
ногами» — это ровно тот баг, который не видно ни в одном скриншоте превью: атлас
складывается строками сверху вниз, `DataTexture.flipY === false`, и `tileRect()`
обязан начинать UV с первой строки арта (со сдвигом на кромку), а `FACES` —
отдавать вершине `y = 1` именно `v = 0`. Проверка проходит по всем 88 тайлам и
сверяет ещё и кресты растений: нижняя вершина цветка обязана брать нижнюю строку
тайла, а высота квада — равняться `plantH`.

Там же, в §6, закреплено второе, что глазами в превью не ловится: **какая грань
какой тайл обязана брать**. `FACES` идёт в порядке +X, −X, +Y, −Y, +Z, −Z, поэтому
`F_TOP = 2`, `F_BOTTOM = 3`. Когда там числились 0 и 1, мир не чернел и тест
ориентации проходил — просто верх травы получал боковой тайл, бока ствола — кольца
с макушки, снег — землю, а флаг «волны» навешивался на боковые грани воды вместо
поверхности (отсюда дрожащая белая полоса на озере). Проверка сверяет имя тайла
под UV каждой грани для травы, снега, брёвен, камня и воды, плюс отдельно — что
`light.w` стоит на верхней грани воды и его нет на боковых.

Кстати, «шахматка» на пляже текстурным багом не была: на границе воды генератор
кладёт гравий вперемешку с песком (`песок 91 · гравий 26` клеток в кадре со
скриншота), и рядом с однотонным песком это читается как битая текстура.

Содержимое тайлов — пятна по 2–4 px, а не попиксельный перебор: `soft()` строит
значения по сетке и на 16 px даёт заметную диагональную решётку («царапины»), а
`grain()`/`speckles()` с большой амплитудой на дистанции превращаются в рябь и
шахматку. Для однотонных материалов (песок, снег, камень, земля, трава) поэтому
используется `mottle()`, а `npm run test:calm` сторожит метрику: средняя разность
соседних пикселей ≤ 9.5 и высокочастотная доля ≤ 1.15 (для узорных — только доля,
иначе кирпич и булыжник законно контрастны).

Генерация — как в Minecraft: кольцо чанков вокруг игрока достраивается каждый кадр.
Важны четыре детали:

* **один общий бюджет кадра** (6 мс на генерацию + свет + меширование) с явной
  политикой в `streamPlan()`: при кадре длиннее 20 мс работа ужимается в 2.5 раза,
  при запасе и большой очереди — растягивается в 1.4. Два предохранителя, оба из
  жалоб игроков:
  * **пол 3.4 мс** — раньше ужимание было бездонным, и на слабой машине генерация
    получала доли миллисекунды: мир не доставался за игроком («иду — впереди
    пустота»);
  * **взрыв 16 мс, пока очередь глубже 60 чанков** — это стартовая прогрузка
    (радиус 10 = 441 чанк) и смена радиуса. Там тормозить контрпродуктивно:
    мир ещё не видно, а игрок уже смотрит по сторонам. 80 % бюджета отдаётся
    генерации, пока очередь не рассосётся;
  Раньше лимиты ещё и складывались (9 + 2.5 + 8 мс), из-за чего каждый второй кадр
  гарантированно пропускался: мир «подлагивал» при ходьбе. Сбои генерации и
  меширования больше не прячутся в консоль — они видны в F3 как `сбой: ген N, меш M`;
* **упавшая генерация не оставляет вечной дыры**: `World.ensureChunk` кладёт чанк
  в кэш только после удачной `terrain.generate`, а при исключении выбрасывает
  оболочку и повторяет до трёх раз. Раньше `set()` шёл до генерации, и любой
  thrown внутри (HMR-несовместимость методов `Terrain` — классический случай)
  оставлял в мире пустой чанк: «чанк есть», `needsMesh` нет → стриминг к нему
  не возвращается → невидимый мир при растущем `chunkCount`. Деревенская
  застройка и `villageAt` обёрнуты в деградацию (`genDegraded`): нет метода —
  нет деревни, но мир честный. Сбои видны на экране: toast + счётчик в F3.
  Регрессия — `npm run test:stream` (проверяет и то, и другое, включая
  «Terrain без деревенских методов»);
* **`getChunk` не кэширует отрицательный ответ**: у `World` был одно-слотовый
  кэш `getChunk`, и он запоминал тоже «чанка нет». Мешеер лезет в соседей через
  `NeighborCache`, трогает отсутствующего соседа, кэш отравляется; чанк
  генерируется, а `getChunk` продолжает отвечать «нет» → `neighborsReady` врёт
  → чанк выбрасывается из очереди меша и обратно не возвращается. Симптомы:
  `чанков 351 · мешей 88 · в очереди 0`, мир «генерируется», а чанки
  невидимые. Регрессия — `npm run test:stream` (юнит на кэш + «все чанки
  радиуса имеют геометрию, очередь пуста»);
* **очередь работы отделена от состояния**: `chunk.needsMesh` — «меш устарел», а
  `world.dirtyMesh` — только то, что реально можно мешировать сейчас (соседи есть,
  чанк в радиусе). Без этого чанки вне кольца копились в очереди сотнями и сортировались
  каждый кадр;
* **упреждение по скорости**: кольцо смещается туда, куда идёшь, поэтому недостроенное
  остаётся позади, в тумане, а не перед носом;
* **верх меша — по занятости чанка**: `buildChunkMesh` идёт до `chunk.hmax + 2`, а не до
  `HEIGHT` (96). Экономия скромная, ~3% (замер `npm run bench:mesh`: 5.22 → 5.06 мс на
  чанк), но она же защищает от лишней работы над пустым небом при малых высотах.

Выгрузка — с гистерезисом (+3 чанка),
чтобы чанки упреждения не выбрасывались в том же кадре. Один упавший чанк не роняет цикл:
ошибка логируется, стриминг продолжается.

поэтому любой сид восстанавливается из `localStorage` целиком. Освещение — небо по
высоте + свет от факелов (BFS по 14 уровням), затенение граней и ambient occlusion
запекаются в вершины.
