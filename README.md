# lite-os
легкая операционная ситсема

## LiteCraft — 3D-воксельная игра (браузер)

Песочница в духе Minecraft: бесконечный процедурный мир, копка и установка блоков,
деревья, руды, пещеры, вода, факелы, цикл дня и ночи, сохранение мира в браузере.
Всё на Three.js, без единого внешнего ассета — текстуры, звуки и музыка генерируются кодом.

### Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # прод-сборка в dist/
npm test           # смоук-тест всей игры в Node (физика, добыча, крафт, мобы, сохранение, UI)
npm run test:shaders  # GLSL-парсер: все uniforms объявлены, синтаксис в порядке
npm run test:api      # все this.<модуль>.<метод>() из main.js реально существуют
npm run test:villages # деревни: плотность, планировка, детерминизм на границах чанков
npm run bench:mesh    # профиль стриминга: мс на генерацию и меширование чанка
npm run test:calm     # численная проверка «спокойных» тайлов (шум на 1px = рябь)
npm run test:uv       # ориентация и посадка текстур: атлас ↔ UV ↔ грани (ловит «вверх ногами»)
npm run test:stream   # политика стриминга: бюджет не должен морить очередь (ловит «пустые чанки»)
npm run render:tiles  # лист тайлов атласа в PNG, чтобы смотреть текстуры глазами
npm run render     # PNG-превью мира без браузера (софтверный растеризатор по тем же мешам)
```

### Управление (клавиатура и мышь)

| Клавиша | Действие |
| --- | --- |
| W A S D / стрелки | движение |
| Shift | красться (не свалиться с края) |
| Ctrl, двойное W | бег |
| Пробел | прыжок, в воде — всплыть; двойное нажатие — креативный полёт |
| ЛКМ (держать) | копать блок |
| ПКМ (держать) | ставить блоки подряд |
| средняя кнопка | скопировать блок в руку |
| колесо / 1…9 | выбор слота хотбара |
| E | инвентарь и крафт (в креативе — палитра всех блоков) |

На телефоне появляется сенсорный джойстик и кнопки обзора/копки; настройка
`Сенсорное управление` в меню включает их принудительно.

### Выживание, крафт и мобы

Новый мир стартует в **выживании**: блоки добываются и тратятся, инструменты нужно
крафтить. Творческий режим включается галкой в настройках (блоки не тратятся, урон
не страшен, хотбар заполняется палитрой).

* **Инвентарь** — 9 слотов хотбара + 27 в рюкзаке, стак 64. Клик по клетке берёт стек,
  клик по другой кладёт/меняет. `Q` — выбросить.
* **Добыча** — из камня летит булыжник, из травы — земля, из листвы — саженцы.
  Скорость зависит от инструмента: `кирка` для камня/стекла, `топор` для дерева,
  `лопата` для земли/песка/дёрна; неподходящим инструментом блок копается втрое медленнее.
* **Инструменты и оружие** — 16 предметов (дерево, камень, железо, алмаз × кирка,
  топор, лопата, меч): скорость 2.4 / 3.6 / 5.6 / 8.2, урон 2 / 3 / 5 / 7.
* **23 рецепта** — доски, палки, верстак, факелы, булыжник, стекло, кирпич, все инструменты.
  Простые собираются в инвентаре, каменные и железные — только рядом с верстаком (в 4 блоках).
* **Мобы** — свинья, корова, овца (мирные, день), сумеречник и пещерник (агрессивные
  ночью и в темноте; сумеречник горит на солнце). У мобов своя воксельная геометрия,
  та же физика AABB-коллизий, они пасутся, убегают от удара, падают и тонут.
  С них падает мясо, кожа, шерсть, уголь, светокамень. Число мобов вокруг — в настройках
  (0 = выключить).

### Растения

Травинки, папоротники, цветы, пшеница и саженцы рисуются крестовиной высотой
`plantH` из `BLOCKS` (0.42–0.72 блока), а не на весь блок, и растут куртинами:
плотность модулируется шумом по сетке 2×2 (`hash2(x >> 2, z >> 2)`), поэтому на
лугу чередуются заросли и вытоптанные пятна. Раньше в саванне травинка была на
30% клеток и стояла в полный блок — вместо луга получалось поле зелёных
штырьков, что и выглядело как «сломанные текстуры».

### Мир

Десять биомов (равнины, лес, тайга, саванна, пустыня, снега, болото, горы, пляж, океан),
горные хребты, пещеры с озёрами, руды по глубине, снежные вершины. Трава и листва
окрашиваются оттенком биома через вершинный атрибут `tint`, поэтому один и тот же
тайл на лугу, в лесу и в саванне выглядит по-разному. Дальность прорисовки — до 16 чанков
(~256 блоков): туман начинается на 55% дистанции и полностью закрывает только край
прокрутки, так что мир не обрывается в пустоту. Чанки генерируются по запросу для любого
сид-координате — проверено тестом на ±5100 блоков.

### Деревни

Регион 96×96 блоков с ~28% вероятностью становится деревней, если биом подходящий
(равнины, лесостепь-саванна, пустыня, тайга, снега), рельеф плоский (перепад ≤ 6) и
суше уровня моря. Планировка — сетка 3×3 клетки 32 блока: улицы между клетками,
в центре площадь с колодцем и четырьмя фонарями, по углам дома, на сторонах света —
огороды и дворы. Строит генератор из чанковых координат, как деревья: любой чанк
восстанавливается независимо, и на стыках дома не разъезжаются (это отдельная проверка
в `npm run test:villages` — застройка сравнивается при двух порядках генерации).

* **Дом**: стены из досок (в пустыне — песчаник, в тайге и снегах — булыжник), углы и
  притолока из брёвен, окна из стекла, дверь на стороне площади, пол, перекрытие,
  крыша с парапетом и коньком, труба, светокамень-фонарь на коньке у высоких домов.
* **Огород**: грядки (`farmland`) через ряд с пшеницей, пруд, стог сена, изгородь из брёвен.
* **Житель** (`mobs.js`): появляется только в деревне, мирный, несёт изумруд.
  Агрессивные мобы в деревне не спавнятся — площадь освещена и безопасна.
* Новые блоки: **грядка**, **пшеница**, **стог сена**, **изумруд** (id 59–62; `BLOCKS`
  индексируется по id, поэтому новые записи — только в конце массива, за инструментами).

Вход в деревню игра отмечает подсказкой, в отладочной панели (F3) видно `деревня`,
а заодно стоимость стриминга в мс на кадр — по ней удобно проверять, что мир больше не
дёргается.

### Что внутри

```
src/engine/    шум, блоки, генератор мира (биомы, пещеры, руды, деревья), мешинг чанков
src/render/    атлас пиксельных текстур, материал чанков (AO + свет + туман), небо, частицы, руки
src/game/      игрок и физика, рейкаст по вокселям, инвентарь, крафт, мобы, WebAudio-синтез, сохранения
src/ui/        HUD, инвентарь, меню, настройки, тач-управление
dev/           тесты и отладочные скрипты (смоук-тест гоняет игру на заглушках DOM)
```

Текстуры — атлас 512×512 (16×16 ячеек по 32 px, тайл 16 px + 8 px дублированной
кромки). Маппинг: `NearestFilter` вблизи, `LinearMipmapLinear` + анизотропия до 8 вдали —
иначе наискось уходящая в гориз поверхность рябила сеткой. Степень двойки выбрана не
случайно: с ней mipmap легален в любом WebGL-контексте.

Растения (крестовины) — без `fullBright`: свет берут общий с рельефом, иначе в
полдень луг светится кислотно-жёлтым на фоне затенённой земли. Силуэт
папоротника расширяется книзу (кверху — читается как перевёрнутый), высота
квада 0.38–0.62 из `plantH`, а `alphaTest` у твёрдого материала 0.15, не 0.4:
на дальних mipmap-уровнях 16-пиксельный тайл усредняется до α 0.2–0.4, и с
порогом 0.4 трава пропадала за полем зрения.

Ориентация тайла закреплена тестом `npm run test:uv`, потому что «текстуры вверх
ногами» — это ровно тот баг, который не видно ни в одном скриншоте превью: атлас
складывается строками сверху вниз, `DataTexture.flipY === false`, и `tileRect()`
обязан начинать UV с первой строки арта (со сдвигом на кромку), а `FACES` —
отдавать вершине `y = 1` именно `v = 0`. Проверка проходит по всем 79 тайлам и
сверяет ещё и кресты растений: нижняя вершина цветка обязана брать нижнюю строку
тайла, а высота квада — равняться `plantH`.

Содержимое тайлов — пятна по 2–4 px, а не попиксельный перебор: `soft()` строит
значения по сетке и на 16 px даёт заметную диагональную решётку («царапины»), а
`grain()`/`speckles()` с большой амплитудой на дистанции превращаются в рябь и
шахматку. Для однотонных материалов (песок, снег, камень, земля, трава) поэтому
используется `mottle()`, а `npm run test:calm` сторожит метрику: средняя разность
соседних пикселей ≤ 9.5 и высокочастотная доля ≤ 1.15 (для узорных — только доля,
иначе кирпич и булыжник законно контрастны).

Генерация — как в Minecraft: кольцо чанков вокруг игрока достраивается каждый кадр.
Важны четыре детали:

* **один общий бюджет кадра** (6 мс на генерацию + свет + меширование) с явной
  политикой в `streamPlan()`: при кадре длиннее 20 мс работа ужимается в 2.5 раза,
  при запасе и большой очереди — растягивается в 1.4. Два предохранителя, оба из
  жалоб игроков:
  * **пол 3.4 мс** — раньше ужимание было бездонным, и на слабой машине генерация
    получала доли миллисекунды: мир не доставался за игроком («иду — впереди
    пустота»);
  * **взрыв 16 мс, пока очередь глубже 60 чанков** — это стартовая прогрузка
    (радиус 10 = 441 чанк) и смена радиуса. Там тормозить контрпродуктивно:
    мир ещё не видно, а игрок уже смотрит по сторонам. 80 % бюджета отдаётся
    генерации, пока очередь не рассосётся;
  Раньше лимиты ещё и складывались (9 + 2.5 + 8 мс), из-за чего каждый второй кадр
  гарантированно пропускался: мир «подлагивал» при ходьбе. Сбои генерации и
  меширования больше не прячутся в консоль — они видны в F3 как `сбой: ген N, меш M`;
* **упавшая генерация не оставляет вечной дыры**: `World.ensureChunk` кладёт чанк
  в кэш только после удачной `terrain.generate`, а при исключении выбрасывает
  оболочку и повторяет до трёх раз. Раньше `set()` шёл до генерации, и любой
  thrown внутри (HMR-несовместимость методов `Terrain` — классический случай)
  оставлял в мире пустой чанк: «чанк есть», `needsMesh` нет → стриминг к нему
  не возвращается → невидимый мир при растущем `chunkCount`. Деревенская
  застройка и `villageAt` обёрнуты в деградацию (`genDegraded`): нет метода —
  нет деревни, но мир честный. Сбои видны на экране: toast + счётчик в F3.
  Регрессия — `npm run test:stream` (проверяет и то, и другое, включая
  «Terrain без деревенских методов»);
* **`getChunk` не кэширует отрицательный ответ**: у `World` был одно-слотовый
  кэш `getChunk`, и он запоминал тоже «чанка нет». Мешеер лезет в соседей через
  `NeighborCache`, трогает отсутствующего соседа, кэш отравляется; чанк
  генерируется, а `getChunk` продолжает отвечать «нет» → `neighborsReady` врёт
  → чанк выбрасывается из очереди меша и обратно не возвращается. Симптомы:
  `чанков 351 · мешей 88 · в очереди 0`, мир «генерируется», а чанки
  невидимые. Регрессия — `npm run test:stream` (юнит на кэш + «все чанки
  радиуса имеют геометрию, очередь пуста»);
* **очередь работы отделена от состояния**: `chunk.needsMesh` — «меш устарел», а
  `world.dirtyMesh` — только то, что реально можно мешировать сейчас (соседи есть,
  чанк в радиусе). Без этого чанки вне кольца копились в очереди сотнями и сортировались
  каждый кадр;
* **упреждение по скорости**: кольцо смещается туда, куда идёшь, поэтому недостроенное
  остаётся позади, в тумане, а не перед носом;
* **верх меша — по занятости чанка**: `buildChunkMesh` идёт до `chunk.hmax + 2`, а не до
  `HEIGHT` (96). Экономия скромная, ~3% (замер `npm run bench:mesh`: 5.22 → 5.06 мс на
  чанк), но она же защищает от лишней работы над пустым небом при малых высотах.

Выгрузка — с гистерезисом (+3 чанка),
чтобы чанки упреждения не выбрасывались в том же кадре. Один упавший чанк не роняет цикл:
ошибка логируется, стриминг продолжается.

Мир — чанки 16×16×128, правки хранятся как карта `x,y,z → id` и поверх генерации,
поэтому любой сид восстанавливается из `localStorage` целиком. Освещение — небо по
высоте + свет от факелов (BFS по 14 уровням), затенение граней и ambient occlusion
запекаются в вершины.
