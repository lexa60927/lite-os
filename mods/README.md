# Свои моды и шейдеры

> **Статус с v0.4.3: в игре загрузка своих модов ВЫКЛЮЧЕНА** (`MODS_IN_GAME = false` в
> `src/main.js`): файлы из `mods/` не подхватываются, сохранённые в браузере моды не
> читаются, секции «Моды» в настройках нет. Причина: GLSL мода попадает в ОДИН общий
> воксельный материал, и если на чьём-то драйвере программа не собралась — исчезает
> весь мир (небо, облака, рука и рамка цели живут на своих материалах и остаются).
> Сама система цела: `src/game/mods.js`, этот справочник, `npm run test:mods` и
> `game.mods` из консоли работают — обратно всё включается одной строкой
> `MODS_IN_GAME = true`. А игра с 0.4.3 в любом случае обязана остаться видимой:
> при несобранной программе она спускается на лёгкий материал, затем на базовый
> (`src/render/fallbackMaterial.js`), ступень и текст ошибки драйвера показывает F3,
> то же самое можно померить дома: `npm run diag`, `npm run diag:sweep`.


Мод — это один JS-объект. Его можно положить файлом сюда (`mods/<имя>.js`) или
вставить текстом в **Настройки → Моды** (работает и на собранной версии, которую
отдаёт GitHub Pages, — там сборщика нет, поэтому мод сохраняется в localStorage
этого браузера).

```js
// mods/moy-mod.js
export default {
  id: 'moy',                    // короткое имя, строчные буквы; по нему мод выключается
  name: 'Мой мод',
  enabledByDefault: false,      // false = игра выглядит как без мода, пока не включишь галкой
  tiles: { … },                 // 1) пиксель-арт
  blocks: [ … ],                // 2) блоки и предметы
  recipes: [ … ],               // 3) крафт
  ore: { … },                   // 4) что закапывать в рельеф
  mobs: { … },                  // 5) существа
  shader: { … },                // 6) свой шейдер
};
```

Порядок секций — это порядок применения, и он не случаен: атлас строится по
`tiles`, `blocks` получают id по порядку (id блока — это **байт** в чанке), рецептам
нужны уже существующие ключи, а `shader` собирается в материал при его создании.

## tiles — пиксель-арт 16×16

Никаких png: тайл описывается примитивами, теми же, что рисуют ванильные блоки.

```js
tiles: {
  // поле + вкрапления (руда, камень)
  ruby_ore: { base: '#6f6f73', speck: '#d81b52', density: 0.34, seed: 12 },
  // сетка кирпичей/досок + оттенок
  ruby_block: { base: '#b3154c', grid: 4, shade: 0.2 },
  // предмет: готовый силуэт (gem | rod | ingot | dust | ball), светлая и тёмная грань
  item_ruby: { base: '#e2386a', icon: 'gem', light: '#ff8fb0', dark: '#8d0f36' },
  // свой код рисования — tl это PixelTile (fill, noise, blobs, speckles, rect, shade…)
  krakatuk: { paint: (tl) => { tl.fill('#123'); tl.blobs('#f0f', 4, 3, 2.4); return tl; } },
}
```

Своя `paint`-функция работает и в файле, и в текстовом поле: мода хранится как текст, а не как JSON.

Поля: `base`, `colors` (массив оттенков вместо автоматических), `speck` +
`density` (вкрапления), `blobs`, `grid` + `shade` (сетка), `border`, `icon`,
`grain` (сила шума), `soft: false` (частый шум вместо пятен), `seed`, `paint`.

## blocks — блоки, предметы, инструменты

```js
blocks: [
  { key: 'ruby_ore', name: 'Рубиновая руда', tile: 'ruby_ore', hard: 2.4, sound: 'stone', drops: 'ruby' },
  { key: 'ruby', name: 'Рубин', tile: 'item_ruby', item: true },
  { key: 'ruby_lamp', name: 'Рубиновая лампа', tile: 'ruby_block', torch: true, glow: 0.85 },
  { key: 'ruby_pick', name: 'Рубиновая кирка', tile: 'item_ruby',
    tool: { kind: 'pickaxe', mine: ['stone', 'glass'], speed: 6.8, damage: 6, uses: 300 } },
  { key: 'pie', name: 'Пирог', tile: 'item_ruby', food: 6 },          // +3 сердца за укус (food/2)
  { key: 'ruby_dust', name: 'Пыль', tile: 'item_ruby', item: true, bonusOf: 'ruby_ore', bonus: 0.2 },
  // правка существующего блока — через patch, id остаётся прежним
  { key: 'dirt', patch: { hardness: 0.2 } },
]
```

Флаги формы: `item`, `plant: 0.5` (крестовина высотой 0.5), `torch` (факел: тонкий,
полная яркость), `liquid`, `transparent` (стекло: `cutout` + не непрозрачный),
`glow: 0..1` (свет от блока), `solid`, `opaque`, `breakable`, `hard`/`hardness`,
`inset`, `tinted` (окрашивается биомом), `plantH`.
Прочее: `name`, `tiles: { top, bottom, side }` (вместо `tile`), `drops` (ключ
предмета вместо самого блока), `bonusOf` + `bonus` (шанс бонусного дропа —
считается из координат, поэтому у соседа по сети тот же результат), `food`,
`info: 'spawn' | 'time'` (компас/часы: показываются в подсказке под хотбаром и в F3).

`sound` — не только звук: именно по нему подбирается инструмент (`mine: ['stone']`
у кирки совпадает со `sound: 'stone'` у блока). Награда за это: кнопка «подходящий
инструмент» не нужна — работает вся готовая логика скорости.

## recipes

```js
recipes: [
  { out: 'ruby_block', n: 1, need: [['ruby', 4]], name: 'Рубиновый блок', table: true },
  { out: 'ruby', n: 4, need: [['ruby_block', 1]], name: 'Рубины из блока' },
]
```

`table: true` — собирается только рядом с верстаком (в 4 блоках). Неизвестный ключ в
`out` или `need` — мод не применяется вовсе, а причина видна в панели: полу-рабочий
рецепт хуже, чем честный отказ.

## ore — своё в рельефе

```js
ore: { block: 'ruby_ore', into: 'stone', min: 2, max: 18, chance: 0.5, veins: 9, size: 5 }
```

Массив — можно несколько жил. Проход идёт ПОСЛЕ генерации ванильного мира и ДО
правок игрока, поэтому: (а) без модов генерация байт-в-байт прежняя, (б) то, что вы
поставили или сломали, мод не перекроет. `chance` — доля попыток, `veins` — сколько
жил на чанк, `size` — длина жилы. Случайности нет: жила считается хешем из
координат и сида, и все игроки комнаты видят одно и то же.

## mobs

```js
mobs: {
  rubygolem: { name: 'Рубиновый голем', color: '#c2185b', hp: 24, size: 1.25, speed: 1.9,
               hostile: true, damage: 4, jumps: true, darkOnly: true,
               drops: [{ block: 'ruby', n: 2 }] },
}
```

`color` — и туловище, голова и четыре ноги соберутся сами (своя текстура
`mob_<key>` генерируется автоматически). Хочешь другую форму — дай `parts`:
`{ p: [x, y, z], s: [w, h, d], tile: 'мой_тайл', shade: 0.9, limb: 1 }`
(`limb` — конечность, она машет при ходьбе).
Поведение: `passive` (по умолчанию) или `hostile` + `damage` + `aggro` (дистанция
агрессии); `hp`, `w`/`h` (размер хитбокса), `speed`, `jumps` (перепрыгивает блок),
`burnsInSun` (сгорает днём, как высушенный), `darkOnly` (спавнится только в темноте:
в небе и в пещерах), `villageOnly` (рядом с деревней, как деревенский житель).

## shader — свой шейдер

Четыре точки вставки, от дешёвой к дорогой. Все они — **куски GLSL внутри наших
шейдеров**, а не отдельная программа: у материала чанков одна программа, и three
не пересобирает её на каждое движение.

| куда | что там есть | когда |
| --- | --- | --- |
| `frag` | `col` (vec3, меняй его), `vWorld`, `vUv`, `uTime`, `uDay`, `uDusk`, `uNight`, `tileIndex()` | цвет блока до тонмаппинга — оттенок, контраст, «мой блок светлее» |
| `fragFinal` | то же, плюс уже применена дымка | экранный вид |
| `vert` | `pos` (локальная вершина), `world` (vec4, меняй `world.y`), `uv`, `uTime` | покачивание, «ветер» у своих блоков |
| `post` | `c` (vec4 кадра), `vUv`, `uTime`, `uUnder`, `uDusk`, `uNight` | только на уровне «Ультра» (там есть пост-проход) |

```js
shader: {
  name: 'Тёплый закат',
  uniforms: { uAmount: 0.55 },          // → слайдер 0..1 в панели «Моды»
  frag: `
    float k = clamp(uDusk * uAmount, 0.0, 1.0);
    col = mix(col, col * vec3(1.16, 1.0, 0.84) + vec3(0.022, 0.004, 0.0), k);
  `,
  // функция вместо строки — чтобы номер тайла не хардкодить (игра подставит его сама):
  fragFinal: (m) => 'if (tileIndex() == ' + m.tileIndex('ruby_ore') + '.0) col = mix(col, vec3(1.0, 0.35, 0.5), 0.25);',
}
```

Правила, без которых мод не принимается (битый GLSL — это пустой мир вместо мира,
и именно поэтому проверка злая, а игра дополнительно откатывается на базовый
материал, если программа всё-таки не собралась):

- только выражения внутри функции: **нельзя** `void main`, `#include`, `#define`,
  `#if`, `uniform`/`varying` своими руками — свои значения пиши в `uniforms`, их
  игра объявит сама (`number → float`, `[x, y] → vec2`, `[r, g, b] → vec3`);
- нельзя переобъявлять имена нашего шейдера — вставка попадает в тот же `main()`,
  и повторное объявление читается компилятором как `redefinition`, то есть материал
  не собирается вовсе: `col`, `c`, `tex`, `sky`, `occ`, `blk`, `nrm`, `lit`, `lit0`,
  `shade`, `sunGate`, `fg`, `lcAlpha`, `world`, `pos`, `mv`, `wpos`, `fogD`, `lin`,
  `expf`, `vUv`, `vWorld`, `vTint`, `vFog`, `vLight`, `position`, `normal`, `uv`,
  и наши функции `wave`, `waterSlope`, `skyLike`, `tileIndex`, `aces`.
  Писать в `gl_FragColor` и `discard` тоже нельзя: результат берётся из `col`
  (в `post` — из `c`);
  <sub>Так игра живёт с v0.4.2: раньше список был короче, локал `alpha` в общем
  шейдере столкнулся с `float alpha` пользовательского мода — и мир стал пустым.
  Теперь имя `alpha` свободно, а если шейдер мода всё-таки не соберётся, игра сама
  вернёт базовый материал и напишет тост с именем виновника.</sub>
- можно: `sin cos pow clamp mix smoothstep length dot normalize texture2D vec3…`,
  то есть обычный GLSL-ES 1.0 без расширений;
- ≤ 6000 символов на вставку, скобки обязаны быть сбалансированы;
- объявленная `uniform` должна хотя бы в одной вставке использоваться, иначе
  непонятно, зачем она.

Код мода вставляется **в отдельный блок `{ … }`** в каждом месте, поэтому локальные
переменные разных модов не сталкиваются. Вставки выполняются на всех уровнях
шейдеров, кроме `post` (ему нужен «Ультра»), и работают и в креативе, и в выживании.

Свечения в этом API нет специально: `UnrealBloomPass` из игры удалён по просьбе
«не должно быть свечения, это некрасиво». Хочешь «магии» — поднимай насыщенность и
светимость локально через `col`, а не яркость всего кадра.

## Включить, выключить, применить

Одно правило, которое надо знать заранее: id блока — байт в чанке, атлас строится
один раз. Значит, набор включённых модов с блоками лучше держать стабильным. Если
выключить один из двух таких модов, id блоков второго сдвинутся, и старые блоки
начнут выглядеть чужими (правки с несуществующими id игра при загрузке выбрасывает,
так что чанк хотя бы не исчезнет). Новые блоки при этом всегда встают в конец
списка — на ванильный мир мод повлиять не может никак.

- Настройки → «Моды»: чекбокс на каждом моде, textarea для своего мода, кнопки
  «Сохранить мод» и «Применить шейдеры сейчас».
- **Моды, которые трогают блоки/тайлы/мобов, применяются только перезагрузкой
  (F5)**: атлас строится один раз, а id блоков живут в сохранённых мирах —
  «поменять на лету» означало бы разъехаться с чужими сохранениями и соседями по сети.
- Чистый `shader` (без новых блоков и тайлов) применяется кнопкой без перезагрузки:
  материал пересоздаётся, геометрия остаётся.
- Консоль браузера для отладки:
  ```js
  game.mods.snapshot()                 // что принято, что нет и почему
  game.mods.register({ id: 'probe', shader: { frag: 'col.g += 0.1;' } })
  game.mods.setUniform('uAmount', 0.9) // крутить ручку, не трогая файлы
  game.mods.applyShaders()
  ```

## Лимиты (жёсткие, потому что движок упирается в них)

- id блока — байт: **не больше 256 блоков всего** (ванильных сейчас 72, значит на
  моды ~180);
- атлас — 16×16 ячеек по 32 px: **не больше 256 тайлов** (ванильных 88);
- 64 мода, ≤ 6000 символов GLSL на вставку;
- имена (`id`, `key`, тайлы): строчные латинские буквы, цифры, `_`, `-`, 2–24 символа.

## Как проверить мод, не открывая браузер

```bash
# 1. примет ли реестр (и почему нет)
node --input-type=module -e "
const m = (await import('./mods/moy-mod.js')).default;
const { register } = await import('./src/game/mods.js');
console.log(JSON.stringify(register(m.id, m), null, 2));"

# 2. как выглядят тайлы — лист атласа в PNG, мод применяется до сборки листа
node dev/render-tiles.mjs /tmp/tiles.png --mod mods/moy-mod.js
```

`ok: false` → в `error` список причин. Тесты игры: `npm run test:mods`
(он же сторожит инвариант «без модов игра байт-в-байт прежняя»).

После применения мода сетка атласа сдвигается: ванильных тайлов 88, значит первый
тайл мода — ячейка 88 (6-й ряд, 9-я колонка). Так что «пропавшая» текстура обычно
означает не ошибку, а то, что смотришь не в ту ячейку.
